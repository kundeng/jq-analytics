# Functions of jq-analytics

Generated by `tools/skill_build.py` from `analytics.jq` and the read-out notes. For each family: a table of its public functions (how each is called, what it is for), then for each function the comment that stands above its definition in the library, which says what the arguments mean and which fields the result has. An argument with `$` is a value; one without is a filter, run on each row (write `.site`, not `site` or `"site"`). Rules for ties and errors beyond what is said here are in the README's Reference.

## Math: arrays of numbers

| Call | What it is for |
|---|---|
| `nonnull`, `count_nonnull`, `sum_nonnull`, `mean` | The list without its nulls, and the count, sum and mean of what is left |
| `min_nonnull`, `max_nonnull`, `min_by_nonnull(f)`, `max_by_nonnull(f)` | The least and greatest value of a column, and the whole row that holds it |
| `var_samp`, `var_pop`, `stddev_samp`, `stddev_pop` | Variance and standard deviation: how far the values lie from their mean |
| `quantile_disc($p)`, `quantile_cont($p)`, `median`, `quantiles_disc($ps)`, `quantiles_cont($ps)` | The value below which a share `$p` of the data lies, with `$p` from 0 to 1 |
| `round_to($d)` | A number rounded to `$d` decimal places, as SQL's and a spreadsheet's `ROUND(x, d)` |

`nonnull`

```text
the input array without nulls
```

`count_nonnull`

```text
number of non-null values
```

`sum_nonnull`

```text
sum of non-null values; null when there are none (jq's add returns null for [] but counts nothing)
```

`mean`

```text
arithmetic mean of non-null values; null when none. Plain `add / length` divides by a count
that includes nulls: [1, null, 3] gives 1.33 there and 2 here.
```

`min_nonnull`

```text
least and greatest non-null value; null when none, as SQL's MIN and MAX. jq's own min and max do
not skip nulls: null sorts below every number, so [null, 1, 3] | min is null there and 1 here.
```

`min_by_nonnull(f)`

```text
the row whose f is least (greatest), rows with a null f left out; null when none (SQL ARG_MIN,
ARG_MAX). Ties: the first such row for min, the last for max, as jq's min_by and max_by.
```

`var_samp`

```text
variance and standard deviation: sample (divide by n - 1, null below 2 values) and population
(divide by n, null when none). Two-pass: mean first, then squared deviations.
```

`quantile_disc($p)`

```text
Quantiles over non-null values, p in [0, 1]; null when none.
quantile_disc: nearest rank, an element of the data: the value at 1-based rank ceil(n * p) of the
  sorted values, at least rank 1. DuckDB's quantile_disc gives the same (checked by the tests).
quantile_cont: linear interpolation at h = (n - 1) * p between the neighbours of h, the rule of
  DuckDB's quantile_cont and median, Excel PERCENTILE.INC and Power Query PercentileMode.ExcelInc.
```

`quantiles_disc($ps)`

```text
several quantiles at once, as DuckDB's list form: null (not a list of nulls) when no values
```

`round_to($d)`

```text
round to $d decimal places, halves away from zero, on the binary double (so 1.005 becomes 1.0,
because 1.005 is stored as 1.00499999...). Null stays null.
```

## Types

| Call | What it is for |
|---|---|
| `parse_ts` | `parse_ts` turns a timestamp string into seconds since 1970-01-01 UTC, the number that every time function in the library takes |
| `cast_columns($schema)` | Gives the named columns of a table their types: text to number, timestamp or boolean, and anything to string |

`parse_ts`

```text
a timestamp string to UTC epoch seconds (fractions kept). Accepts "YYYY-MM-DD HH:MM:SS" or "T",
optional fraction, optional "Z" or +HH:MM / +HHMM offset. No offset means UTC (as ServiceNow
and Splunk's _time strings store it). null and "" give null; anything else is an error, never
a silent empty: that includes a date or time that does not exist, such as 30 February.
Unlike strptime("%z"), the offset is applied.
Fast path: the common 19-character form ("2026-08-12 13:05:00") skips the regex, which was most of
the cost (at 500,000 rows in the Python jq package, 24.7 s with the regex, 7.5 s without); its
dashes, colons and digits are still checked, by fromdateiso8601's own format, and a bad one is the
same error.
```

`cast_columns($schema)`

```text
cast the named columns of every row. $schema = {column: "number" | "timestamp" | "string" | "boolean"}.
"" and null become null. A value that does not parse is an error naming the column and value
(Power Query's rule), never a null. Numbers must look like JSON numbers: jq 1.7.1's tonumber
accepts " 12" and jq 1.8's refuses it, so the pattern decides instead of the version.
A schema column that a row lacks is added to it as null, so every row comes out with the same columns.
```

## Time zones and calendar

| Call | What it is for |
|---|---|
| `tz($name)` | The rules of one zone, looked up by name |
| `tz_offset($tz)` | The zone's offset from UTC at one moment, in seconds |
| `local_time($tz)` | The local clock reading of a moment in a zone, as an object with the date, the clock fields and the weekday |
| `format_local($tz; $fmt)` | An instant as readable local text: "2026-03-08 03:00" in Detroit rather than the UTC hour |
| `hours_between(a; b)` | The hours from one moment to another, with no rounding; null when either is missing |

`tz($name)`

```text
the transition rules of one IANA zone, from the generated tzdata block above (from the tzdata package; covers
1970 to 2100). Unknown zone is an error. No process TZ is read anywhere in this file.
tz_rules is a 27 KB literal that jq rebuilds on every call (0.8 ms), so a program that converts
many rows looks the zone up once: tz("America/Detroit") as $det | ... | local_time($det).
```

`tz_offset($tz)`

```text
UTC offset in seconds at the input epoch; $tz is a zone name or the object tz($name) returned
```

`local_time($tz)`

```text
the local wall clock of the input epoch in zone $tz (a name or tz($name)), as an object:
{date: "YYYY-MM-DD", year, month (1-12), day, hour, minute, second, weekday (0 = Sunday),
 offset_s, local_epoch (epoch of the wall clock read as if it were UTC)}
```

`format_local($tz; $fmt)`

```text
format_local: the input epoch as text in zone $tz with strftime directives ("%Y-%m-%d %H:%M"),
the zone's offset applied, daylight saving included; %z is written as +HHMM and %Z as the zone
name, from the zone tables, not from the machine's clock settings
```

`hours_between(a; b)`

```text
hours from epoch a to epoch b, exact (no rounding); null when either is null
```

## Grouping

| Call | What it is for |
|---|---|
| `group_agg(keyf; aggf)` | Group a table by a key and compute something per group: one output row per group, holding the key and the results |

`group_agg(keyf; aggf)`

```text
group rows by keyf and aggregate each group with aggf (applied to the group's array of rows).
Output: one row per group, in order of first appearance (group_by sorts by key instead).
A key that is an object is merged into the output row; any other key goes in field "key".
aggf must return an object. Null keys form one group, as in SQL GROUP BY.
```

## Several tables at once

| Call | What it is for |
|---|---|
| `split_by(tagf)` | One list of rows into an object of tables, one table per value of a tag |
| `keep_tables($names)` | Only the named tables of an object of tables |
| `shape` | For each table: how many rows it has and which fields its rows use |

`split_by(tagf)`

```text
split a stream of rows into an object of tables by a tag: rows with the same tagf value form one table,
named by that value as a string (a null tag gives the table "null"). A host that can pass only one
stream hands over several tables this way: one stream, with a field saying which table each row belongs to.
Two different tags with the same name as text (1 and "1", or null and "null") are an error: one
table would otherwise replace the other.
```

`keep_tables($names)`

```text
keep only the named tables (drop the rest before a heavy step or before output)
```

`shape`

```text
for checking a pipeline midway: each table's row count and field names (sorted)
```

## Joins

| Call | What it is for |
|---|---|
| `join_on($right; lkey; rkey; cond; $kind; $suffix)`, `join_on($right; lkey; rkey; cond; $kind)` | The general flat join: one output row per matching pair, with the fields of both rows |
| `join_inner($right; lkey; rkey)`, `join_left($right; lkey; rkey)`, `join_full($right; lkey; rkey)`, `join_semi($right; lkey; rkey)`, `join_anti($right; lkey; rkey)` | The five kinds of equality join under their own names |
| `join_nest($right; lkey; rkey; cond; $as)` | Every left row exactly once, with one new field holding the array of its matching right rows |
| `lookup($dim; lkey; dkey; $as)` | Attaches the one matching row of a second table under a new field |
| `join_overlap($right; lkey; rkey; lstart; lend; rstart; rend)` | Pairs with the same key whose time intervals overlap |
| `join_asof($right; lkey; rkey; ltime; rtime; $max_age)`, `join_asof($right; lkey; rkey; ltime; rtime)` | For each left row, the right row with the same key and the latest time at or before the left row's time |

`join_inner($right; lkey; rkey)`

```text
equality joins: join_on with no condition; semi and anti return left rows only, with no right fields
```

`join_nest($right; lkey; rkey; cond; $as)`

```text
nested join: every left row once, with field $as holding the array of its matching right rows
(empty when none). Never multiplies rows. Power Query's Table.NestedJoin.
```

`lookup($dim; lkey; dkey; $as)`

```text
lookup: attach exactly one record of a dimension table under field $as (null when none).
A key that appears twice in the dimension is an error, so a lookup can never multiply rows.
```

`join_overlap($right; lkey; rkey; lstart; lend; rstart; rend)`

```text
interval overlap: pairs with the same key whose intervals overlap, each closed at its start and open at its end ([start, end)); a null end means still open. Flat and inner; a start or end field named the same on both sides comes out twice, the right one with "_right". An interval with no start, or one that ends before it starts, is an error (as in merge_intervals).
```

`join_asof($right; lkey; rkey; ltime; rtime; $max_age)`

```text
As-of join (left outer): for each left row, the right row with the same key whose rtime is the
greatest rtime <= the left row's ltime (DuckDB's ASOF LEFT JOIN ... ON l.k = r.k AND l.t >= r.t).
$max_age, when not null, rejects a match older than that: ltime - rtime must be <= $max_age.
Ties on rtime: the first such right row in input order (DuckDB 2.0.0 gave the same on the test
fixture; pandas merge_asof takes the last; SQL leaves it open). No match, or a null key or time
on the left: the left row alone. Right rows with a null key or time are dropped.
```

## Windows

| Call | What it is for |
|---|---|
| `window(part; ord; $col; wf)` | Adds one column to a table, computed per partition in a chosen order, and returns the rows in the order they came in |
| `row_number` | 1, 2, 3 and so on for the rows of a partition, in its order |
| `rank_by(f)` | SQL's `RANK()`: rows with the same value share a rank, and the next rank skips |
| `lag(f; $k)`, `lead(f; $k)` | The value from the row `$k` places before the current one (`lag`) or after it (`lead`) |
| `running_sum(f)` | The sum of a value from the start of the partition up to each row |
| `moving_mean(f; $n)` | The mean of a value over the current row and the `$n - 1` rows before it |

`window(part; ord; $col; wf)`

```text
Window over partitions: split rows by part (first appearance), sort each partition by ord
(stable: ties keep input order), call wf on the sorted partition (an array of rows), which must
return an array of the same length, and write its i-th value into field $col of the i-th row.
Rows come back in input order. Frames are ROWS frames (each row by itself), not SQL's default
RANGE frame, which gives tied rows the same running value.
```

`row_number`

```text
window value functions: input is one sorted partition (array of rows)
```

`rank_by(f)`

```text
rank with gaps (SQL RANK) by f over the partition's order: tied f values share a rank
(a row's rank is its position plus one, minus the earlier rows that share its value; grouping
once gives that count for every row, where counting per row took the square of the partition)
```

`running_sum(f)`

```text
running sum of f, ROWS frame from the partition start: nulls skipped; null until the first non-null
```

`moving_mean(f; $n)`

```text
moving mean of f over the current row and the $n - 1 rows before it (fewer at the start); nulls skipped
```

## Reshape

| Call | What it is for |
|---|---|
| `unpivot($keep; $name; $value)` | Wide to long: every column that is not kept becomes a row of its own |
| `pivot($cols; rowkey; colf; valf; agg)` | Long to wide: one output row per row key, and one column per name in a list the caller gives |
| `rename_fields($names)` | New names for the fields listed, in every row of a table |
| `prefix_fields($prefix)` | A prefix in front of every field name of a table |

`unpivot($keep; $name; $value)`

```text
unpivot: every field not in $keep becomes its own row {keep fields..., $name: field, $value: value}.
Null values are kept (Power Query's example drops them). Within a row, fields come out sorted by
name, so every engine agrees (jq and jaq keep insertion order, gojq sorts keys).
```

`pivot($cols; rowkey; colf; valf; agg)`

```text
pivot: one output row per rowkey (an object) and one column per name in $cols (Power Query's
pivotValues), holding agg applied to the array of valf values whose colf (as a string) is that
name. A name with no matching rows gives null; colf values not in $cols are dropped.
```

`rename_fields($names)`

```text
rename_fields: $names is an object {old name: new name}. Every row's field with an old name gets
the new one and keeps its value and its place in the row; a row without the field is left as it
is. All names change at once, so {a: "b", b: "a"} swaps two fields. A new name that is already
another field of the row is an error: one of the two values would be lost.
```

`prefix_fields($prefix)`

```text
prefix_fields: every field name of every row with $prefix in front ("cmdb_" turns site into
cmdb_site). Put on one table before a join, it makes every output field show which table it came from.
```

## State machines over time

| Call | What it is for |
|---|---|
| `state_blocks(entity; time; state)` | A table of events into a table of blocks: per entity, how long it spent in each state, in order |
| `transitions(entity; time; state)` | One row per change of state: from which state, to which, and when |
| `sessions(entity; time; $gap)` | Events grouped into sessions: per entity, a new session starts when the gap since the previous event is greater than a limit |
| `runs(f)` | Run-length encoding: consecutive items with the same value become one row with the value, where the run starts and how long it is |

`state_blocks(entity; time; state)`

```text
state_blocks: per entity, events sorted by time (stable), consecutive events with the same state
merged into one block: {entity key..., state, start (time of its first event), end (time of the
next block's first event, null for the entity's last block), duration (end - start, null when
open), events (how many events it merged)}. A repeated state does not restart the clock: an
assignee change while the status stays Open is still the same Open block. The entity key is
merged in as group_agg does (an object key's fields, or field "key"). Order: entities by first
appearance, blocks by time. An event with a null time is an error.
```

`transitions(entity; time; state)`

```text
transitions: one row per change of state: {entity key..., from, to, at (time of the change)}
```

`sessions(entity; time; $gap)`

```text
sessions: per entity, events sorted by time; a new session starts when the gap since the previous
event is greater than $gap. Rows: {entity key..., session (1, 2, ... within the entity), start,
end (time of its last event), events}.
```

`runs(f)`

```text
runs: run-length encoding of an array in its given order: consecutive items with the same f value
become {value, start (0-based position of the first), n}. Streaks are the long runs.
```

## Hierarchies

| Call | What it is for |
|---|---|
| `tree_paths(id; parent)` | Adds to every node its `ancestry`, the ids from its root down to itself, and its `depth`, 0 for a root |
| `tree_rollup(id; parent; value)` | Adds to every node the total of a value over the node and everything below it |

`tree_paths(id; parent)`

```text
tree_paths: adds to every node `ancestry` (the ids from its root down to itself) and `depth`
(0 for a root). A parent id that is not a node, a cycle, or an id on two rows is an error.
Each node's ancestry is built once: a walk up stops at the first ancestor already done and the
ancestries are then filled in from there down, so the cost follows the size of the output, not
the square of the depth.
```

`tree_rollup(id; parent; value)`

```text
tree_rollup: tree_paths, plus `subtree`: the node's own value plus the values of all its
descendants, at any depth. A null value counts as 0.
```

## Graphs

| Call | What it is for |
|---|---|
| `reachable(from; to; $start)`, `hops(from; to; $start)` | `reachable` lists every node that can be reached from `$start` along the edges, nearest first |
| `shortest_path(from; to; $start; $goal)` | The route from `$start` to `$goal` with the fewest edges, as `{path, cost}`, where `cost` is the number of edges |
| `shortest_path(from; to; weight; $start; $goal)` | The route with the lowest total weight, where `weight` is a filter giving each edge's weight |
| `topo_order(from; to)` | A dependency order: one row per node with a `level`, such that every edge goes from a lower level to a higher one |
| `components(a; b)` | Connected groups, with the edges read as undirected: one row per node, `{node, component}`, where `component` is the smallest node of the node's group |

`reachable(from; to; $start)`

```text
reachable: every node that can be reached from $start along directed edges from -> to, at any
number of hops, nearest first. $start itself is never listed, even when a cycle leads back to it:
each node appears once and the start counts as already seen. Cycles are safe.
```

`hops(from; to; $start)`

```text
hops: one row per node that can be reached from $start along directed edges, the start itself
included at 0: {node, hops}, where hops is the number of edges on the shortest route; nearest
first, and within one distance in the order the search meets them.
```

`shortest_path(from; to; $start; $goal)`

```text
shortest_path, four arguments: the route from $start to $goal with the fewest edges, as
{path: [the nodes from start to goal], cost: the number of edges}; null when there is none;
{path: [$start], cost: 0} when they are the same node. Among routes of equal length, the one a
breadth-first search following edges in input order finds first.
```

`shortest_path(from; to; weight; $start; $goal)`

```text
shortest_path, five arguments: the route with the lowest total weight (weights are numbers >= 0;
anything else is an error), same output with cost the total. Among routes of equal cost, the one
found first. It settles the nearest open node by scanning them all, with no priority queue: fine
for a few thousand nodes, slow beyond.
```

`topo_order(from; to)`

```text
topo_order: a dependency order of the nodes of a directed graph. One row per node: {node, level},
sorted by level then node: level 0 for a node nothing points to, otherwise one more than the
highest level among the nodes that point to it, so every edge goes from a lower level to a higher
one and the nodes of one level do not depend on each other. A cycle is an error naming a node on it.
```

`components(a; b)`

```text
components: connected groups, edges read as undirected. One row per node: {node, component},
where component is the smallest node of its group in jq's sort order. Rows sorted by node.
```

## Measures in a context

| Call | What it is for |
|---|---|
| `rollup_levels($levels; cell)` | A report at several levels: one output row per group at each level listed |
| `rollup($dims; cell)` | The levels of a hierarchy: all the fields, then one fewer from the right, down to the grand total |
| `measure(f)`, `measure_with(f; change)`, `share_of(f; change)` | The three functions a cell is written with |
| `without_filter($dim)`, `only_filters($dims)`, `with_filter($at)` | Three context changes that edit `.at`, the filter object, and nothing else |
| `shift($dim; $k)` | A context change that moves the filter on `$dim` to a neighbouring value: `shift("month"; -1)` is the previous month, `shift("month"; 1)` the next |
| `on_calendar($dim; $values)` | Makes `shift` and `to_date` on `$dim` step through a list of periods the caller gives, in place of the values present in the data |
| `to_date($dim)` | A context change that turns the filter on `$dim` into "everything up to and including this value", with the other filters kept |

`rollup_levels($levels; cell)`

```text
rollup_levels: one output row per group at each listed level. $levels is a list of field lists,
for example [["region", "product"], ["region"], []]; [] is the grand total. Each output row is the
level's fields, a level name ("region/product", or "all") and the fields of cell. Rows come level
by level in the order listed, sorted by the level's values within a level. Nothing is added up
from finer cells: every level is computed from rows, so a median or a ratio is right at the total.
A row missing a level's field forms its own group (null). No input rows give no output rows.
```

`rollup($dims; cell)`

```text
rollup: the hierarchy of $dims: every field, then one fewer from the right, down to the grand
total (SQL's GROUP BY ROLLUP). rollup(["region", "month"]; ...) gives region/month, region, all.
```

`measure(f)`

```text
inside a cell: measure f on the cell's own rows
```

`measure_with(f; change)`

```text
inside a cell: measure f on the rows of a changed context (DAX's CALCULATE). change is one or
more of without_filter, only_filters, with_filter, shift, to_date, piped. A shift past the first or last
value has no context, and measure_with returns null without running f.
```

`share_of(f; change)`

```text
inside a cell: measure f here divided by f in the changed context; null when that is null or 0
```

`without_filter($dim)`

```text
context changes. Each takes a context and returns one.
remove one filter (ALL, REMOVEFILTERS). Written as .at |= del(...), not del(.at[$dim]): gojq's del
copies the whole context, every row included, which cost 0.03 s per cell at 37,960 rows.
```

`shift($dim; $k)`

```text
move to the $k-th neighbouring value of $dim (-1 is the previous one). Neighbours are the field's
distinct values over all rows, sorted, so "previous" is the previous value that has rows anywhere,
not the previous calendar period. No filter on $dim (a total row) or no such neighbour: no context.
A field that is not a level of the report has no list of values to step through: an error.
```

`on_calendar($dim; $values)`

```text
on_calendar: make shift and to_date on $dim step through $values, in the order given, instead of
through the values present in the data: measure_with(revenue; on_calendar("month"; $months) | shift("month"; -1))
is the previous calendar month even when it has no rows (the measure then runs on no rows).
$values is every period in order, for example calendar(...) | map(.year_month) | unique. A cell
whose own value is not in $values has no context after a shift. to_date compares values, so the
list has to sort the way it is ordered: "2026-03" does, "Mar" does not.
```

`to_date($dim)`

```text
everything up to and including this value of $dim, other filters kept (a running total, DATESYTD
when the year is another filter). No filter on $dim: unchanged.
```

## Shapes in and out

| Call | What it is for |
|---|---|
| `unnest(f; $as)`, `unnest_outer(f; $as)` | One row per element of an array field |
| `flatten_fields($sep)` | Nested objects become columns named by their path, so `{"user": {"dept": "x"}}` gives a column `user.dept` |
| `nodes_from_nested(id; children)` | A nested tree, where each node holds its children in an array, becomes node rows, each with a `parent` field |
| `rows_from_map($as)` | An object keyed by id becomes rows, with the key in field `$as` |
| `fill_grid($keys; $time; $step; $fill)` | Completes a time series: every combination of the key fields gets a row at every time step from the earliest time to the latest, and a missing combination gets a filler row |
| `to_map(key)` | Rows become an object keyed by `key`, for looking a row up by id |
| `nested_from_nodes(id; parent; $as)` | The reverse of `nodes_from_nested`: node rows with an id and a parent become a nested tree, each node's children in an array in field `$as` |
| `node_link(from; to)` | Edge rows become the `{nodes, links}` object that graph tools such as networkx, d3 and Cytoscape read |
| `to_csv($cols)`, `to_tsv($cols)`, `to_table($cols)` | A table as text for another tool or a person: CSV, TSV, or padded columns for a terminal |
| `rows_from_arrays`, `from_csv` | CSV text into rows, the other direction |
| `flatten_paths($sep)`, `unflatten_fields($sep)` | Nested rows as flat columns and back |
| `drop_empty` | A document without empty values at any depth: null, `""`, `[]` and `{}` go, as fields and as array items, and a container that ends up empty goes with them |

`unnest(f; $as)`

```text
unnest: one row per element of the array at f, the element in field $as. A row whose array is
empty or null is dropped, as SQL's UNNEST drops it; unnest_outer keeps it once with $as null
(LEFT JOIN LATERAL). A value at f that is neither an array nor null is an error naming the row's
position. Elements come out in array order, rows in input order.
```

`flatten_fields($sep)`

```text
flatten_fields: nested objects become columns named by their path joined with $sep
({"user": {"dept": "x"}} gives "user.dept"). Arrays and scalars are left as values, for unnest to
take; an empty object stays as the value {}. Two paths that flatten to the same name are an error.
(jq's own flatten flattens arrays; this flattens the objects inside each row.)
```

`nodes_from_nested(id; children)`

```text
nodes_from_nested: a nested tree (each node holding its children in an array at `children`)
becomes node rows, each with `parent` set to its parent's id (null for a root) and the children
array removed. The input is one root object or an array of roots. Rows are in depth-first order.
```

`rows_from_map($as)`

```text
rows_from_map: an object keyed by id becomes rows, the key in field $as, sorted by key. A value
that is not an object becomes {($as): key, value: v}. Sorted because gojq does not keep an
object's key order, so the order the keys were written in cannot be the same on every engine.
A value that already has a field named $as is an error: it would replace the key.
```

`fill_grid($keys; $time; $step; $fill)`

```text
fill_grid: every combination of the $keys fields' values (in first appearance) at every time from
the earliest to the latest in steps of $step seconds; a missing combination gets a row with the
key fields, the time field and $fill. $keys and $time are field names; times are epoch seconds
and must sit on the grid (an offset from the earliest that is a multiple of $step), else an
error. Without the filled rows a lag or a moving mean steps over an empty period as if it were
the next one.
```

`to_map(key)`

```text
to_map: rows become an object keyed by `key` (as a string). A duplicate key is an error; jq's
own INDEX(key) keeps the last row silently.
```

`nested_from_nodes(id; parent; $as)`

```text
nested_from_nodes: node rows (id, parent) become a nested tree, each node's children in an array
in field $as, the roots in an array. Checked with tree_paths first, so a missing parent or a
cycle is the same error as there.
```

`node_link(from; to)`

```text
node_link: edge rows become the node-link form graph tools read (networkx, d3, Cytoscape):
{nodes: [{id}], links: [row + {source, target}]}. Nodes are in order of first appearance.
```

`to_csv($cols)`

```text
to_csv: a header line, then one CSV line per row, columns in the order of $cols (null: every
field name, sorted); a stream of strings, so run jq with -r. A null is an empty cell; a nested
value is written as its JSON text.
```

`to_tsv($cols)`

```text
to_tsv: as to_csv, with tabs; a tab, line break or backslash in a value is escaped as jq's @tsv does
```

`to_table($cols)`

```text
to_table: the rows as plain-text columns for a terminal, a header line first, each column as wide
as its longest value, two spaces between, no trailing spaces; run jq with -r
```

`rows_from_arrays`

```text
rows_from_arrays: [header, row, row, ...] as rows; a short row's missing cells are null, a row
longer than the header or a header that repeats a name is an error
```

`from_csv`

```text
from_csv: the text of a CSV file (jq -Rs) as rows, by RFC 4180: the first record names the
fields; quoted fields may hold commas, line breaks and doubled quotes; CRLF or LF line ends; blank
lines skipped. Every value stays a string, for cast_columns. Reads one character at a time:
about 5 s a megabyte in jq 1.7, 2 s in jaq; past a few megabytes, DuckDB's read_csv.
```

`flatten_paths($sep)`

```text
flatten_paths: like flatten_fields, arrays included: every leaf becomes a column named by its
path joined with $sep, array positions as numbers ({"tags": ["x"]} gives "tags.0"); an empty
array or object stays as the value. Two paths that give the same name are an error.
```

`unflatten_fields($sep)`

```text
unflatten_fields: the reverse of flatten_paths and flatten_fields: a field "a.b.0" becomes
{a: {b: [value]}}; a part made only of digits is an array position, so a key "0" cannot survive
```

`drop_empty`

```text
drop_empty: a document without null, "", [] or {} at any depth, fields and array items alike;
a container left empty by that is removed too. false and 0 stay. Any value in. (For nulls only,
jq's own del(.. | nulls).)
```

## Intervals

| Call | What it is for |
|---|---|
| `intervals_from_events(resource; holder; time; kind; ttl)` | Builds validity intervals from an event log: who held a resource (a seat, an address, a session id) and from when to when |
| `join_within($intervals; lkey; rkey; ltime; rstart; rend)` | A left outer join of rows that have a time to the interval of the same key that contains that time |
| `merge_intervals(key; start; fin)` | Per key, intervals that overlap or touch become one |
| `concurrency(start; fin)` | How many intervals are open over time: one row `{t, open}` per moment the count changes |

`intervals_from_events(resource; holder; time; kind; ttl)`

```text
intervals_from_events: validity intervals built from an event log. A resource (an address, a
seat, a session id) has at most one holder at a time. For each event, `kind` gives "open" or
"hold" (evidence that `holder` has `resource` at `time`: a grant, a renewal, a start, a
keep-alive), "release" (the holder gives it up), or null (ignored). `ttl` gives how many seconds
a hold stays valid without another one, or null when holds do not expire.
  - A hold opens an interval, or extends the open one when it is from the same holder: its end
    becomes the later of its end and time + ttl (null when this hold's ttl is null).
  - An interval ends in exactly one way, in `ended_by`: "released" (a release from its holder, at
    that time), "taken_over" (a hold from another holder while it is still valid, at that time),
    "lapsed" (its end passed before the next event on the resource), or "open" (still open at the
    end of the data; its end is the last hold + ttl, or null).
  - At the same time on one resource, events apply in the order open, hold, release. A release from someone
    who does not hold the resource, or when nothing is held, is ignored.
  - `start_seen` is true when the interval's first event was "open": a "hold" may be a renewal of
    something that began before the data does.
`last` is the time of the interval's last hold: the last evidence, which is what there is to go
on when an open interval has no end.
One row per interval: {resource, holder, start, end, last, events, start_seen, ended_by}; resources in
order of first appearance, intervals in time order. Intervals of one resource never overlap.
A kind other than the three, or a null time on an event with a kind, is an error naming the event.
```

`join_within($intervals; lkey; rkey; ltime; rstart; rend)`

```text
join_within (left outer): each left row with the interval of the same key whose [rstart, rend)
contains the left row's ltime; a null rend means still open. No such interval, or a null key or
time on the left: the left row alone. When several intervals of a key contain the time, the one
that started last. Merged like every flat join: a field name on both sides that is not the
key comes out twice, the right one with "_right". Use it for "who held this at T"; join_asof is for "the latest value at or before T".
```

`merge_intervals(key; start; fin)`

```text
merge_intervals: per key, intervals that overlap or touch become one row
{key..., start, end, merged (how many went in)}; keys in order of first appearance, intervals in
time order. A null end is open-ended and absorbs everything of its key that starts after it.
```

`concurrency(start; fin)`

```text
concurrency: how many intervals are open over time: one row {t, open} per moment the count
changes, in time order (`end` is a jq keyword, so the parameter is called fin). An interval counts from its start up to, not including, its end; one
with a null end never stops counting. The peak is `concurrency(...) | max_by(.open)`.
```

## Calendar

| Call | What it is for |
|---|---|
| `calendar($from; $to; $zone)`, `calendar($from; $to)` | A date table: one row per day from `$from` to `$to`, both included |

`calendar($from; $to; $zone)`

```text
calendar: one row per day from $from to $to inclusive (both "YYYY-MM-DD"), ignoring its input:
  {date, year, quarter, month, day, weekday (0 = Sunday), day_of_year,
   iso_year, iso_week   (weeks start Monday; week 1 holds the year's first Thursday; a day near
                         New Year can belong to the neighbouring ISO year),
   us_week              (weeks start Sunday; week 1 holds 1 January: a spreadsheet's WEEKNUM(d, 1)),
   year_month "2026-03", year_quarter "2026-Q1", iso_year_week "2026-W09",
   start, end}          epoch seconds of local midnight in $zone (a name or tz($name)) at the
                        day's start and end, so a day is the interval [start, end): 23 or 25
                        hours long when the clocks change, and join_within puts an event in its day.
calendar($from; $to) is in UTC. Not a date, $from after $to, or an unknown zone: an error.
```

## Event paths: funnels, cohorts, retention

| Call | What it is for |
|---|---|
| `funnel_steps(entity; time; step; $steps; $within)` | How far each entity gets through an ordered list of steps |
| `funnel(entity; time; step; $steps; $within)` | The funnel as a table: one row per step with how many entities reached it, and that count as a fraction of the previous step's and of the first step's |
| `cohorts(entity; period; $periods)` | One row per entity: its key and `cohort`, the earliest period in which it has an event |
| `retention(entity; period; $periods)` | Of the entities first seen in a period, how many have at least one event in each later period |

`funnel_steps(entity; time; step; $steps; $within)`

```text
funnel_steps: how far each entity gets through the ordered steps in $steps. An entity reaches
step n when it has events for steps 1 to n in time order (a later step at the same time as the
one before counts). With $within (seconds; null for no limit) every step must happen within that
long of the entity's first step, and the entity is credited with the deepest chain any of its
first-step events can start: an early first step that times out does not hide a later one that
completes. One row per entity that reaches step 1, entities in order of first appearance:
{entity key..., depth (1 to the number of steps), times (the time of each step reached)}.
Events whose step is not listed are ignored. An empty step list, a step listed twice, or a null
time on an event of a listed step is an error.
```

`funnel(entity; time; step; $steps; $within)`

```text
funnel: one row per step, in order: {step, entities (how many reached it), from_previous,
from_first}: the count divided by the previous step's and by the first step's; null where the
divisor is zero, and from_previous is null on the first step. A funnel only narrows.
```

`cohorts(entity; period; $periods)`

```text
cohorts: one row per entity, in order of first appearance: {entity key..., cohort}, the earliest
period, in $periods order, in which it has an event. $periods is every period in order, for
example calendar(...) | map(.year_month) | unique. A period not in the list is an error.
```

`retention(entity; period; $periods)`

```text
retention: of the entities first seen in a period (a cohort), how many have at least one event
in each later period. One row per cohort and period, from the cohort's own period to the last in
$periods: {cohort, period, offset (periods after the cohort's; 0 for its own), entities,
cohort_size, rate (entities / cohort_size)}. The table is complete: a period in which nobody of
the cohort is active has a row with 0. Periods with no first-time entities form no cohort.
```

## Distributions, profiles, diffs

| Call | What it is for |
|---|---|
| `mode` | The most frequent non-null value of a list |
| `value_counts` | One row per distinct non-null value of a list, with its count and its share of the non-null values, most frequent first |
| `bin_edges($lo; $hi; $n)`, `histogram($edges)` | A histogram of a list of numbers: how many fall in each bin |
| `corr(x; y)` | Pearson's correlation of two columns: 1 when they rise together on a straight line, -1 when one falls as the other rises, near 0 when there is no straight-line relation |
| `profile` | A first look at a table: one row per column, saying how many rows have it, how many are null or empty, how many distinct values it holds, of which types, and its smallest and largest value |
| `diff_tables($old; key)` | `diff_tables` reports what changed between two versions of a table that share a key: one row per key that was added, removed or changed |
| `diff_docs($old)` | What changed between two versions of a document of any shape, such as a configuration before and after: one row per path that differs |

`mode`

```text
mode: the most frequent non-null value of a list; among equally frequent values the smallest in
jq's sort order; null when there is none.
```

`value_counts`

```text
value_counts: one row per distinct non-null value of a list: {value, count, share (of the non-null
values)}, most frequent first, ties by value.
```

`bin_edges($lo; $hi; $n)`

```text
bin_edges: $n + 1 equally spaced numbers from $lo to $hi, the edges of $n bins
```

`histogram($edges)`

```text
histogram: counts of a list of numbers per bin, the bins given by their edges (bin_edges, or any
increasing list): one row per bin {from, to, count}. A bin holds from <= v < to, and the last bin
also holds v == to, as numpy's histogram does. Nulls are skipped. A value outside the edges is an
error, not a dropped value; so are edges that are not at least two increasing numbers.
```

`corr(x; y)`

```text
corr: Pearson's correlation of x and y over the rows where both are non-null; null with fewer than
two such rows, or when either side does not vary. Matches SQL's corr.
```

`profile`

```text
profile: one row per column of a table, columns in name order:
  {column, rows (rows in the table), present (rows that have the field), nulls (rows where it is
   null or absent), empty (rows where it is ""), distinct (distinct non-null values),
   types (jq type name -> count, over the rows that have the field),
   min, max (the smallest and largest non-null value when all non-null values are numbers or all
   are strings; null otherwise)}
```

`diff_tables($old; key)`

```text
diff_tables: what changed between two versions of a table that share a key. The input is the new
table, $old the old one. One row per key that was added, removed or changed, sorted by key:
{key, change ("added", "removed" or "changed"), fields (for a changed row, the fields whose values
differ, in name order; a field present on one side only counts), old, new (the rows; null on the
side that has none)}. Unchanged rows are left out. A key that appears twice in either table, or
a null key, is an error.
```

`diff_docs($old)`

```text
diff_docs: what changed from document $old to the input, any shape: one row per path,
{path, change, old, new}, change "added", "removed" or "changed"; path as getpath takes it.
Objects compare by key, arrays by position (an item moved counts as changed). [] when equal.
```

## Approximate matching

| Call | What it is for |
|---|---|
| `similarity(a; b)` | How alike two strings are, from 0 to 1 |
| `join_fuzzy($right; lblock; rblock; lstr; rstr; $min; $as)` | A left outer join on "most similar string": each left row gets the right row whose string is most like its own, if the similarity reaches a minimum |

`similarity(a; b)`

```text
similarity: how alike two strings are, from 0 to 1: the Dice coefficient over their distinct
character bigrams (twice the bigrams they share, divided by the bigrams of both). Equal strings
give 1, including strings too short to have a bigram; null on either side gives null. It compares
what it is given: lowercase and trim in the expressions if that is wanted.
```

`join_fuzzy($right; lblock; rblock; lstr; rstr; $min; $as)`

```text
join_fuzzy (left outer): each left row with field $as holding {similarity, row} for the right row
of the same block whose rstr is most similar to the left row's lstr, when that similarity is at
least $min; null otherwise. lblock and rblock give an exact key two rows must share to be
compared at all (a site, a first letter): the cost is one comparison per pair of rows that share
a block, so choose blocks that stay small. Among equally similar right rows, the first in input
order. A null block or a null string never matches.
```
